## Fix and automated validation

The old client republished an unchanged named pointer during a Work edit. An
independent Life write could win that key while the Work key won separately,
leaving a permanent cross-generation fence despite complete data. The saved PAC
then omitted the new Work hostname. Work and named pointers now advance
independently. Cross-list operations use immutable deltas and per-pointer receipts
so either delivered half can be reconciled without removing a changed conflicting
record. Incomplete reads reject activation; intentional later deletions do not
resurrect acknowledged operations. Local Pause does not depend on a successful
Sync read. The 0.3.2 Work schema and protected Life namespace remain intact.

## Cleanup and limits

Only the disposable test extension namespace was cleared. A committed 13 deletes;
B received 13 updates, then reported Extension settings 0/0 Running. Both local
Sync stores were empty. Both Chrome accounts were signed out (Disabled / Not
signed in), processes stopped, the local fixture stopped and both temporary
profiles plus the temporary B app removed. The existing Capture app was retained.
The working Chrome profile, published extension and shared account data were not
targeted. No credentials, cookies or account identifiers are in the evidence.

Same-list concurrent full snapshots retain existing last-writer semantics; this
is not a general lossless CRDT. 0.3.2 cannot route Life, although it preserves Life
in Sync. Update named-route devices to 0.4.2; do not leave 0.4.0/0.4.1 named writers
active. Operation history consumes finite Sync quota; quota errors preserve the
previous committed data. An incomplete read retains the previous PAC and reports
failure, so routing of a new hostname is not promised before complete delivery.
